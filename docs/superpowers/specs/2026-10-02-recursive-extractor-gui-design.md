# 递归解压工具（Rerar）设计规格

- 日期：2026-10-02
- 状态：**待用户评审**（评审通过后方可进入实施计划）
- 目标产物：Windows 单文件 GUI exe
- 相关调研：[边界条件与风险登记册](../research/2026-10-02-edge-case-audit.md)

---

## 1. 背景与目标

### 1.1 缘起

`E:\DSH\rerar` 下有两个批处理脚本，用 `for /r` + `7z x` 循环解压嵌套压缩包（最多 20 轮），可选用同名文件夹隔离，可选删除原包。实测确认它们**功能可用**，但存在数据丢失级缺陷。

### 1.2 意图

把这个脚本的能力重写成一个 **Windows 上双击即用、带图形界面、不会弄丢用户文件** 的解压工具，同时覆盖两类使用场景：

- **网盘/资源站资源包**：多层嵌套、常需密码、可能分卷、后缀常被改名
- **普通嵌套压缩包**：标准 zip/rar/7z 多层嵌套，一般无密码

### 1.3 约束（来自用户决策）

| 约束 | 取值 |
|---|---|
| 场景 | 两者兼顾 |
| 解压引擎 | 混合：优先本机 7-Zip，找不到则用内置便携版兜底 |
| 删除策略 | **默认不删**；删除走回收站；解压失败必须有明确提示 |
| 自动化程度 | 全自动：伪装后缀 + 分卷 + 密码字典 |
| 技术方案 | C# WinForms + Windows 自带 `csc.exe` + 内嵌 7-Zip（方案 A） |
| 界面形态 | A 极简单窗口（日志默认折叠，失败清单可展开） |
| 运行环境 | Windows 10 1903+ / Windows 11 x64；.NET Framework 4.8（系统预装） |

### 1.4 成功标准

1. 风险登记册中标记为 v1.0 的全部 fixture 行为符合期望（自动化断言）
2. **零数据丢失不变量**成立：任何失败场景下原包仍存在
3. **零越界写入不变量**成立：解压后目标根之外无任何新增/修改
4. 无 7-Zip 的干净机器上双击即用
5. 原脚本 4 个已知 bug 各有回归测试
6. exe ≤ 5MB，冷启动 ≤ 2s，中文在界面与报告中均正常显示

## 2. 术语

| 术语 | 含义 |
|---|---|
| 归档 | 压缩包文件（zip/rar/7z/tar/…） |
| 权威成员 | 一个分卷集中应交由 7-Zip 打开的那个文件（各族不同，见 §6.6） |
| 暂存目录 | 与最终目标**同卷**的空目录，解压先落在这里 |
| 提交 | 校验通过后把暂存目录改名为最终名字（同卷 rename，原子） |
| 索引 | `7z l -slt` 输出的结构化清单（条目名、大小、属性） |
| 门控 | 判定某个 zip 是否应被递归解开（区别于 OOXML/APK 等） |

## 3. 已验证的技术事实（设计的硬约束依据）

以下均为本机实测结论，登记册有完整 20 条（V1–V20），此处只列驱动设计的关键项：

| 事实 | 对设计的影响 |
|---|---|
| 7-Zip 退出码：正常=0，损坏=2，错密码=2，缺密码(未传 `-p`)=255 | 成功判定**不能只看退出码** |
| `7z x -y` **不能**抑制密码提示 → 脚本永久挂起 | **始终显式传 `-p<候选>`** |
| 回收站删除可用且可恢复（计数 310→311，可按名检索） | "删除走回收站"可落地 |
| 回收站**不是保证**：按卷配额（实测本机有 3245MB/3276MB 小配额卷）；超配额文件被**永久删除** | 删前必须查配额；删后必须核实 |
| `csc /resource:` 嵌入 + 回读无损；`7z.exe`+`7z.dll` = 2.37MB | 单文件 exe 可行，预估 ~2.5MB |
| 7-Zip 26.01 的 `7z.exe` 隔离环境下可独立解 zip 与 7z/LZMA，且自报 Rar/Rar5 | 兜底方案可行；仍同时内嵌 7z.dll 以消除版本差异 |
| `7z l -slt` 机器可读；`x` 尾部给出 `Folders/Files/Size/Compressed` | 预检与**完整性校验**的依据 |
| `-bsp1 -bb1` 进度可解析，但输出**含 CR(0x0D)** | 进度解析器须按 `\r` 切分 |
| 7-Zip **会**按 tar 条目创建 reparse point；相对 `..` 穿越目标在 26.01 被拒绝(exit 2) 但软链留在输出树 | 必须主动拒绝/展平 reparse point；设**版本下限 25.00** |
| 原生 `ZipFile` 不支持 AES 加密 zip（仅普通与 ZipCrypto） | 不能作为通用替代；v1.1 才考虑作为快路径 |
| 本机无需管理员即可创建符号链接（Developer Mode 已启用） | 软链向量是"活"的 |
| 本 `pwsh` 实为 **PowerShell 5.1**；`Start-Process -Environment` 等 PS7 特性不可用 | 构建/验收脚本必须按 PS 5.1 编写 |

## 4. 架构总览

### 4.1 组件与职责

```
┌─────────────────────────────────────────────────────┐
│ MainForm (WinForms, UI 线程)                         │
│  · 拖放/选择目标  · 选项面板  · 预检摘要对话框        │
│  · 两阶段进度     · 可折叠日志  · 失败清单            │
└───────────────┬─────────────────────────────────────┘
                │ 命令 / 进度事件（Invoke 编组，合并到 200ms）
┌───────────────▼─────────────────────────────────────┐
│ ExtractionJob (后台线程, 单一职责：编排)              │
│  1 JobPlanner   → 冻结本轮候选清单                    │
│  2 Preflight    → 体积/空间/密码/长路径 预检           │
│  3 逐归档循环：                                       │
│      Sniffer    → 真实格式（魔数 + 内嵌 + EOCD）      │
│      Gater      → 该不该递归解开（身份门控）           │
│      Indexer    → 7z l -slt 取索引                    │
│      PasswordSvc→ 候选阶梯 + 验证                     │
│      VolumeSvc  → 权威成员/缺卷判定                   │
│      Stager     → 解压到同卷空暂存目录                │
│      Verifier   → 索引 vs 磁盘 比对                   │
│      Promoter   → 同卷改名提交 + 零 reparse 断言      │
│      SafeDeleter→ 仅成功且校验通过才删（回收站+核实）  │
│  4 Reporter    → 汇总表 + 报告导出                    │
└───────────────┬─────────────────────────────────────┘
                │ Process (异步读管道, Job Object)
┌───────────────▼─────────────────────────────────────┐
│ EngineLocator → 本机 7-Zip(≥25.00) 或内置便携版       │
│ Journal       → 追加式运行日志（不可逆步骤前落盘）     │
└─────────────────────────────────────────────────────┘
```

### 4.2 数据流（单个归档）

```
候选文件
  → Sniffer 判真实格式 ──非归档──→ 记为「已跳过·无法识别」并提示可强制尝试
  → Gater 判是否递归 ──拒绝──→ 记为「容器文档·不递归」（绝不删）
  → Indexer 取索引（条目数/总字节，预检上限、冲突、reparse point）
  → [需要密码] PasswordSvc 走候选阶梯，用 7z t 验证
  → Stager: 7z x -o<暂存> -y -p<候选> -bsp1 -bb1
  → Verifier: 磁盘实际 条目数/字节 vs 索引；断言零 reparse point
  → 通过 → Promoter 改名提交 → 复核
  → 失败 → 保留原包；暂存目录改名 <名字> (未完成)；写哨兵
  → 仅当「提交+复核」都通过 且 用户已开启删除 → SafeDeleter
```

### 4.3 关键技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 语言/框架 | C# 5 + WinForms | 只能用系统自带 `csc.exe`（无 SDK/MSBuild） |
| 进程调用 | `Process` + `UseShellExecute=false` + `CreateNoWindow=true` | 不引入 cmd.exe 引号层（避免命令注入与转义地狱） |
| 管道读取 | `OutputDataReceived`/`ErrorDataReceived` 异步事件 | 同步 `WaitForExit()` 后读会**管道死锁** |
| 子进程生命周期 | Win32 **Job Object** + `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` | 主进程崩溃也不留孤儿 7z |
| 删除 | `Microsoft.VisualBasic.FileIO.FileSystem.DeleteFile(..., SendToRecycleBin)` | 已实测可用 |
| 编码 | 7z 传 `-sccUTF-8`；`StandardOutputEncoding` 对齐；报告 UTF-8 **with BOM** | 避免中文乱码 |
| 清单 | 手写 `app.manifest` 经 `/win32manifest:` | PerMonitorV2 + longPathAware；`asInvoker`（不提权） |
| 版本资源 | 脚本合成 Win32 资源经 `/win32res:` | 属性页有中文公司/产品/版本，降低"可疑感" |

## 5. 核心安全不变式（不可协商）

> 这五条是设计骨架。任何实现取舍若违反其中一条，即为缺陷。

**I1 — 成功判定必须基于索引比对，而非 7-Zip 退出码。**
解压前记录索引的条目数与总字节；解压后核对磁盘实际结果。仅退出码为 0 不足以判定成功（"Everything is Ok" 不代表每条都写出）。

**I2 — 任何写入都必须先落"目标同卷的空暂存目录"，校验通过后改名提交。**
这一条同时消灭覆盖、撞名、半成品、提交失败、跨卷非原子等一整类问题。**绝不向非空目录解压。**

**I3 — 删除默认关闭；仅在该归档"提交并复核通过"后才可触发；且必须诚实。**
删前查卷类型与回收站配额；删后**枚举回收站核实**；核实不到就如实报"已永久删除"，绝不谎称"已移入回收站"。不满足回收条件时提供"隔离文件夹"替代。

**I4 — 递归必须按"内容身份"门控，而非魔数放行。**
`.docx/.xlsx/.pptx/.jar/.apk/.epub/.odt/.whl/.nupkg` 本质都是 zip。盲递归会把用户文档拆成散文件；若同时开启删除，就是**文档被销毁**且全程 exit 0。

**I5 — 始终显式传 `-p<候选密码>`。**
`-y` 压不住密码提示（实测），这正是原脚本挂起的根因。绝不允许 7-Zip 等待 stdin。

## 6. 组件设计

### 6.1 MainForm（UI）

单窗口，按界面形态 A 落地：

```
┌──────────────────────────────────────────────┐
│  ⬇  把压缩包 / 文件夹拖到这里                  │
│      或 [选择文件夹…]  [选择压缩包…]           │
├──────────────────────────────────────────────┤
│  ☑ 识别伪装后缀   ☑ 拼合分卷   ☑ 尝试密码字典  │
│  ⚠ 危险操作                                    │
│  ☐ 解压成功后删除原包（移入回收站）             │
│  ▸ 密码设置（可折叠）                          │
├──────────────────────────────────────────────┤
│           [ 开始解压 ]                         │
│  ████████░░░░░░  第 7 / 已发现 23 个包 · 已用 12:31
│  ✅ 已解出 12 个文件 · ⏳ 正在解压 inner.zip     │
│  ❌ 2 个失败 · 🔒 1 个需密码      [查看详情 ▸]  │
└──────────────────────────────────────────────┘
```

**交互决策**：
- **绝不以管理员身份运行**：提权后 UIPI 会静默拦截 Explorer 拖放（拖了没反应、无报错）。若检测到已提权，显示常驻横幅提示改用按钮
- **"选择…"按钮与拖放同等显眼**，且可键盘操作（拖放失效时的兜底入口）
- **不做暗色主题**（WinForms 跟随系统主题做不彻底，半成品更糟）
- 字体显式设为 `Microsoft YaHei UI`；`AutoScaleMode.Dpi` + PerMonitorV2
- 空状态明确写出「**原件默认保留**」，让危险路径不必是显眼路径
- 关闭窗口三选一：继续在后台运行 / 取消并退出 / 返回
- **逐项动作**：失败/跳过/需密码清单里每一行都提供动作按钮——「强制按压缩包尝试」（对应 §6.3 的"永不静默丢弃"）、「输入密码」、「重试」、「打开输出目录」

### 6.2 EngineLocator（引擎定位）

探测顺序，每步都做**功能性自检**（`7z i` 取版本 + 一次真实列目录），不只比版本号：

1. exe 同目录下的 `7z.exe`
2. `%ProgramFiles%\7-Zip\7z.exe`
3. `%ProgramFiles(x86)%\7-Zip\7z.exe`
4. 注册表 `HKLM\SOFTWARE\7-Zip\Path`（**显式读 64 位与 WOW6432Node 两个视图**）
5. 兜底：内置便携版释放到 `%LOCALAPPDATA%\<Vendor>\Rerar\bin\<buildid>\`

**版本下限 25.00**（此前版本存在已在野利用的符号链接目录穿越漏洞）。低于下限则回落到内置副本，并在界面显示实际使用的版本与来源路径。

内置版**不释放到 `%TEMP%`**（最招杀软的路径）。内嵌资源的**期望 SHA-256 在构建时写入程序常量**，每次执行前校验实际文件哈希与之一致（防被 AV 隔离、截断或替换）；写入时先落临时名再 `File.Move` 原子改名。

### 6.3 Sniffer（格式识别）

三档判定，**永不静默丢弃**：

1. **偏移 0 签名**：`PK\x03\x04`(zip)、`Rar!\x1A\x07`(rar/rar5)、`7z\xBC\xAF\x27\x1C`、gzip/bzip2/xz/tar
2. **头部损坏档**：签名不符但在尾部 64KB 内发现 `PK\x05\x06`(EOCD) 或 `PK\x01\x02` → 报"疑似 zip 且头部损坏，可尝试修复"，区别于"损坏"
3. **内嵌档（v1.1）**：在前 2MB 内搜索归档签名（图种/SFX）→ 报"内嵌压缩包"，**保留宿主文件**

**陷阱文件识别**：首字节为 `<!DOCTYPE html`/`<html`/`<?xml` → 报"这是网页而非压缩包，下载可能失败"；下载中后缀（`*.crdownload`/`*.part`/`*.baiduyun.p.downloading`/`.!ut`/`*.td`）→ 报"下载未完成"；0 字节成员视为缺卷。

### 6.4 Gater（递归门控，对应 I4）

拿到索引后按**头部条目内容身份**判定：

| 特征 | 判定 | 处置 |
|---|---|---|
| `[Content_Types].xml` 或 `_rels/` | OOXML (docx/xlsx/pptx) | **默认拒绝递归**，绝不删 |
| `AndroidManifest.xml` + `classes.dex` | APK | 同上 |
| `META-INF/MANIFEST.MF` + `.class` | JAR | 同上 |
| `mimetype` = `application/epub+zip` | EPUB | 同上 |
| `mimetype` = `application/vnd.oasis.opendocument.*` | ODF | 同上 |
| 其余 | 视为归档 | 允许递归 |

拒绝项在高级选项里可显式开启"强制递归容器文档"（默认关）。

### 6.5 PasswordSvc（密码，对应 I5）

**候选阶梯**（顺序固定，界面展示当前进度）：

1. 手动输入的密码
2. 本次运行中**已验证成功**的密码（按归档记录，全局仅作下一个首选）
3. 导入的字典文件（逐行；同时生成变体：原文 + 去首尾空白 + 全角转半角 + 去零宽/NBSP + 前缀剥离）
4. **内置常用字典**（一个精简的公开常用密码列表，随包可查；不做在线更新）
5. 同目录**线索候选**（见下）

**线索采集必须在任何改名/移动/删除之前完成**：
- 文件名与文件夹名（含 `【解压密码：xxx】` 形式）
- 同目录小文本文件（≤256KB 的 `.txt/.nfo/.md/.url/.html/.htm/.ini`），提取 `密码|password|pwd|mima|解压码` 之后的值
- 归档注释（来自 `7z l -slt`）
- 发现的 URL 的**主机名**

**验证方式**：用 `7z t`（测试）或 `l -slt` 验证候选，**绝不用 `x`**——否则每次错误猜测都会写出大量垃圾。

**加密包的成功判据**：只有 exit 0 才算成功；ZipCrypto 存在 1/256 头校验假阳性，因此**缓存密码前必须验证**。

**凭据卫生**：不记录密码到日志或 journal；若 7z 版本无法避免 argv 传递，在界面如实说明该暴露面。

### 6.6 VolumeSvc（分卷）

**分卷族表**（权威成员各不相同，指错即误报"损坏"）：

| 族 | 成员模式 | 应交由 7z 的**权威成员** |
|---|---|---|
| 新式 RAR | `.part1.rar` … `.partN.rar` | `.part1.rar`（第一个） |
| 旧式 RAR | `.rar` + `.r00`/`.r01`… | `.rar`（第一个） |
| ZIP 分卷 | `.zip` + `.z01`/`.z02`… | **`.zip`（最后一个）** |
| 7z 分卷 | `.7z.001`/`.002`… | `.001`（第一个） |

**规则**：
- **默认不做字节拼接**——RAR 每卷有独立头，拼接即损坏，且 200GB 集合再占一份空间。把权威成员交给 7z，让它自行按名寻卷
- 缺卷必须报**具体缺哪一个**（"缺 movie.7z.002；现有 .001、.003–.005"），而非笼统"损坏"
- 分组须为**终止式 token** + 基名一致 + 位宽一致 + 无空洞；若每个分片都带完整归档签名，则判为独立文件

### 6.7 Stager / Verifier / Promoter（对应 I1、I2）

- **Stager**：在**最终目标的父目录**下建短名空暂存目录（保证同卷），`7z x -o<暂存> -y -p<候选> -bsp1 -bb1`
- **Verifier**：
  - 条目数、总字节 与索引比对
  - **遍历暂存树断言零 `FILE_ATTRIBUTE_REPARSE_POINT`**（实测 7z 会创建软链）
  - 断言无路径越界（`Path.GetFullPath` 归一后必须是暂存根的严格子路径）
  - 记录"磁盘名 ≠ 条目名"清单（非法字符/保留名被改写时）
- **Promoter**：同卷 `Directory.Move` 改名提交 → 复核最终路径存在且为目录
- **失败路径**：暂存目录改名为 `<名字> (未完成)` 并写哨兵文件（含归档路径、大小、期望条目/字节数、7z 诊断原文）。**绝不递归删除非本次创建的目录**

### 6.8 SafeDeleter（对应 I3）

前置条件（**全部满足**才允许删除）：
1. 用户已显式开启删除
2. 该归档状态为「完成」且校验通过（**不含**"完成但有 N 个文件失败"）
3. 源卷支持回收站：`GetDriveType` 非 `DRIVE_REMOTE`/`DRIVE_REMOVABLE`，且卷有 `$Recycle.Bin`
4. 文件体积 ≤ 该卷回收站配额

不满足 3/4 时：**不删**，改提供"隔离文件夹"模式（移动到同卷 `_originals_<timestamp>\`），并明确告知用户。

删除后：**枚举回收站核实**该项确实在内；核实不到 → 如实报"已永久删除"并高亮告警。

### 6.9 Journal / Reporter（崩溃恢复与报告）

- **Journal**：`%LOCALAPPDATA%` 下的追加式日志（**绝不放在目标卷**），在每个不可逆步骤**之前**写入并 `Flush(true)`：
  `即将解压` / `已校验：条目数 N 字节 M` / `即将删除：<路径>`
- **启动恢复**：检测到上次异常终止 → 列出缺少完成记录的产物，标记为"未完成"，且**这些归档一律不删原包**
- **Reporter**：每归档一行汇总表（压缩包 / 结果 / 层数 / 文件数 / 失败数 / 输出去向 / 耗时）；导出 CSV/TXT（UTF-8 with BOM）；完整日志流式写文件

### 6.10 进度与日志（长时运行）

- **两阶段进度**：扫描期 `Marquee` + "已发现 N 个压缩包"；解压期定值，分母为**已发现的工作量**（"第 7 / 已发现 23 个包"）。**只显示已用时间**；ETA 标注"粗略"且满 3 个归档后才出现
- **心跳**：解析 `-bsp1` 进度行（按 `\r` 与 `\n` 双重切分）+ 采样子进程 CPU 与输出文件增长；无信号 30s → 显式显示"正在处理大文件，已用 12:31"
- **日志三份存储**：完整流式写文件（可"打开日志文件"）；虚拟化列表只显示尾部 ~2000 行；UI 追加**合并到 150–250ms 一次**
- **取消**：两段式——请求取消 → "正在取消，最长等待 10 秒"倒计时 → 强制 `TerminateJobObject` → 把当前暂存目录标记未完成。**绝不 `Process.Kill()` 了事**

### 6.11 输出布局策略（唯一权威定义）

原脚本的"同名文件夹"直觉是对的，v1.0 沿用并补全所有未定义情形：

| 项 | 规则 |
|---|---|
| 输出根 | **该归档所在目录**（原地），不另设全局输出目录。多文件夹拖入时每个归档各按自己所在目录计算 |
| 目标名 | `<归档名去掉压缩包扩展名>`，需**消毒**：替换非法字符 `: ? * < > \| "`、规避保留设备名（`CON/PRN/AUX/NUL/COM1-9/LPT1-9`）、去尾点与尾空格、长度上限 120 字符 |
| 暂存位置 | 输出根的**兄弟目录**（保证与最终目标同卷，使提交时的改名是原子操作），短随机名 |
| 目标已存在 | 若非空 → 改用 `<名字> (2)`、`(3)`…（**绝不覆盖**，对应 I2） |
| 目标被同名文件占用 | 中止该归档、不回落父目录、**不删原包** |
| 嵌套层 | 第 N 层解出的归档，其输出目录放在**第 N 层的输出目录之内**，且**不再新套一层包装目录**，以抑制 MAX_PATH 增长 |
| 禁止 | **绝不**让输出路径等于任何输入归档自身的路径（否则边读边写） |
| 提交 | `Directory.Move(暂存, 最终)`；失败则报错并保留暂存（改名 `<名字> (未完成)` + 哨兵） |
| 记录 | 每个归档的最终输出目录写入汇总表与报告，界面可"在资源管理器中打开" |

跨卷例外：若暂存与目标无法同卷（例如目标是只读介质），**不启用暂存流程**，直接解压到目标并**逐文件校验**，且该归档**一律不删原包**。

## 7. 错误分类与用户提示

三档，全程可见，且**"无法解压"与"解压出错"是不同状态**：

| 档 | 例子 | 处置 |
|---|---|---|
| **致命** | 7z 缺失、无法写入目标、磁盘空间不足 | 中止整批，单条明确提示 |
| **批次警告** | 需密码已跳过、卷不完整、路径过长、无法识别格式、容器文档已拒绝 | 记入汇总表，红色行，不删原包 |
| **逐文件失败** | 已完成的归档内有 N 个文件失败（长路径/非法名/被占用） | 汇总为一行可展开项，状态记为「完成但有 N 个失败」→ **不删原包** |

批量失败**不以模态框逐个弹出**（200 个失败 = 200 次点击 + 死锁风险）；统一进可筛选表格 + 导出报告。

### 9.2 验收标准

1. §9.1 全部 fixture 行为符合期望，验收脚本输出 PASS/FAIL 表
2. **零数据丢失不变量**：所有失败场景下原包仍存在（断言）
3. **零越界写入不变量**：验收时对每个 fixture 做目标根**父目录快照比对**（新增/修改/删除均须为空）；运行期则以"路径归一后必须是暂存根严格子路径"+"暂存树零 reparse point"断言实现
4. **干净环境可运行**：无 7-Zip 的机器上双击即用
5. 原脚本 4 个已知 bug 各有回归测试：
   - ① 失败仍删包 → fixture 2/3/7 均断言原包仍存在
   - ② 密码提示挂起 → 加密包在**无人工干预**下必须在限定时间内返回「需密码」，不得阻塞
   - ③ GBK/chcp 乱码 → 界面文案、日志文件、导出报告中中文均正常，不出现替换符 `U+FFFD`
   - ④ 分卷残留 → 开启删除时该分卷集**所有成员被一并处置**或明确全部不处置，不留 `.z02`/`.part2.rar` 孤儿
6. exe ≤ 5MB；冷启动 ≤ 2s；报告 UTF-8 中文在记事本中正常
7. `7z.exe` 缺失或版本 <25.00 → 明确中文提示，不崩溃

### 9.3 验证方式

每个 fixture 对应一个可重复运行的 **PowerShell 5.1** 验收脚本（注意：本机 `pwsh` 实为 5.1，不可用 PS7 特性），统一输出 PASS/FAIL 表。这是"实测验收"的落地形式。

## 10. 范围边界

### 10.1 v1.0 必须

§4–§9 描述的全部内容，其中特别包括：递归 + 深度上限（**默认 10 层，可调**；触顶必须**显式列出未处理项**，不静默停止）、暂存/校验/提交、索引比对、身份门控、伪装后缀（偏移 0）、分卷族表与缺卷报告、密码阶梯与线索采集、删除前置条件与回收站核实、预检、进度与可折叠日志、汇总表与报告导出、崩溃 journal、单文件 exe 与内置 7-Zip 兜底、§9 fixture 矩阵。

### 10.2 明确延后（记录在案，不实现）

| 项 | 理由 |
|---|---|
| 图种/内嵌归档扫描（前 2MB） | 增益有限，v1.1 再做 |
| 分卷伪装名"去伪装"（`00删1` 类，需硬链接暂存） | 实现复杂，涉及暂存与回滚，单独排期 |
| 乱码文件名修复动作（CP936↔Unicode 往返探测） | 独立小功能 |
| 原生 `ZipFile` 快路径（AV 加固，无密码 zip 不落地二进制） | 收益真实但需额外边界测试；实测原生不支持 AES，覆盖面有限 |
| 长路径 `\\?\` 全链路 | v1.0 用"预检拒绝 + 明确提示"兜住 |
| 单实例互斥量 | v1.0 用 journal + 目标占用检测缓解 |
| 垃圾清理动作（`__MACOSX/` 等） | v1.0 只报告不删除 |

### 10.3 明确不做

压缩与格式转换 · 网盘登录与下载 · **自更新**（未签名自替换是最招杀软的模式）· **暗色主题** · 多实例并发解压 · 自动删除任何非本次运行产生的文件

## 11. 未决项与风险

### 11.1 仍需实测的行为（实现阶段用专门探针补测）

1. 映射网络盘 / UNC 上 `SendToRecycleBin` 的语义（抛异常 / 失败 / 静默永久删除）
2. 超过卷回收站配额时 API 是抛异常还是静默永久删除
3. tar/zip 的 **hardlink** 条目 7z 如何处理（本会话无可靠构造手段）
4. 本构建是否触发 Defender / 360 / 火绒 启发式（只能在真机矩阵上测）
5. 7z 的 `\\?\` 内部处理是否会让它写出 >260 路径而我方 .NET 调用随后失败（不对称性）

### 11.2 已识别但 v1.0 接受的残余风险

- **未签名 exe 的杀软误报**：结构性，无证书不可根除
- **Smart App Control**（消费版 Win11 强制模式）：会直接拒绝运行；本机是 IoT 企业版 LTSC，**永远测不出该问题**，必须写入 FAQ
- **7-Zip 版本相关行为**：软链遏制等属版本行为，故设版本下限并以"零 reparse point 断言"兜底
